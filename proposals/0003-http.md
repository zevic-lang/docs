# Proposal 0003: HTTP (`Zevic.Http`)

- Status: accepted (2026-11-03, implemented the same day)
- Date: 2026-11-03

## Motivation

Calling a small web API or running a small server cannot be written with the standard library alone.
Calling `curl` through `Process` is possible, but it may not be installed, and handling the result is awkward.

## Proposal

A new standard library module, `Zevic.Http`. The runtime gets only thin socket functions (`zevic_net_*`),
and the HTTP/1.1 protocol is written in Zevic. No external library is used.

### Client

```
import Zevic.Http

let r: Http.Response = Http.Get("http://localhost:8080/hello")?
Console.Println("${r.Status} ${r.Body}")

let p: Http.Response = Http.Post("http://localhost:8080/echo", "text body")?
```

```
class Request {
    Method: String
    Url: String
    Body: String
    fn Init(method: String, url: String)
    mut fn SetHeader(name: String, value: String)
    mut fn SetBody(body: String)
}

class Response {
    Status: I64
    Body: String
    fn Header(name: String) -> Option<String>     // names are case-insensitive
    fn IsOk() -> Bool                             // 200 to 299
}

fn Get(url: String) -> Result<Response, Error>
fn Post(url: String, body: String) -> Result<Response, Error>
fn Send(req: Request) -> Result<Response, Error>
```

- Each connection is closed after one request (`Connection: close`). Redirects are not followed. The body can be delimited by `Content-Length`, by `Transfer-Encoding: chunked`, or by the connection closing.
- Failing to send, failing to read and a malformed response are an `Err` (`ErrorKind.Io`). A 404 or a 500 is not an `Err`; look at `Status`.
- Limit: the body is at most 16 MiB (more is an `Err`).
- The default timeout is 30 seconds.

### Server

```
let server: Http.Server = Http.Listen("127.0.0.1", 0)?     // 0: pick a free port
Console.Println("port ${server.Port()}")
server.Serve((req: Http.Request) => {
    Http.Response.Text(200, "hello ${req.Path()}")
})?                                                         // does not return until Close is called
```

```
fn Listen(host: String, port: I64) -> Result<Server, Error>
class Server {
    fn Port() -> I64
    fn Serve(handler: fn(Request) -> Response) -> Result<Unit, Error>   // one async task per connection
    fn Close()                                                           // ends Serve (call it from another task)
}
// The Request the server receives has Path(), Query(), Header(name) and Body
// Build a Response with Response.Text(status, body) and SetHeader
```

- If the handler panics inside `Serve`, the whole program stops, as the rules for `Task` say.

### Not included (in this proposal)

- **HTTPS (TLS)**: an implementation of the cryptography cannot be written safely without dependencies. An `https://` URL gives an `Err` ("https is not supported yet"). It is to be added later, in a separate proposal, using what the OS offers (OpenSSL, SChannel on Windows, Network.framework on macOS).
- HTTP/2, keep-alive, redirects, cookies, multipart, WebSocket and proxies.

## Alternatives

- Depending on `libcurl`: HTTPS would work, but it is not installed on every OS and it makes the build complicated. It goes against the policy that the standard library has no external dependencies.
- Calling `curl` through `Process`: it depends on whether `curl` is installed.
- A server with a single loop and no `Async`: one slow handler stops everything.

## Impact

- Runtime: `zevic_net_listen`, `zevic_net_accept`, `zevic_net_connect`, `zevic_net_read`, `zevic_net_write`, `zevic_net_close` and `zevic_net_shutdown`, for POSIX and Winsock. On Windows `ws2_32` is linked (unverified).
- Standard library: `Zevic.Http` (depends on `Zevic.Async`).
- No impact on the language or `zevfmt`.

## Tests

- In one program, start the server with `async`, and try GET, POST, 404, chunked bodies, large bodies and headers from the client over the loopback interface (`127.0.0.1`).
- A malformed response, a closed connection and `https://` give an `Err`.
- Nothing goes to the internet (so the tests run in CI).
