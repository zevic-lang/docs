# 提案 0003: HTTP(`Zevic.Http`)

- 状態: 採用(2026-11-03、実装は同日)
- 日付: 2026-11-03

## 動機

Webの小さなAPIを呼ぶ、小さなサーバーを立てる、という用事が、標準ライブラリだけでは書けない。
`Process` で `curl` を呼ぶ方法はあるが、入っているとは限らず、結果の扱いも不便。

## 提案

新しい標準ライブラリ `Zevic.Http`。ランタイムにはソケットの薄い関数(`zevic_net_*`)だけを足し、
HTTP/1.1 のプロトコルは Zevic で書く。外部のライブラリは使わない。

### クライアント

```
import Zevic.Http

let r: Http.Response = Http.Get("http://localhost:8080/hello")?
Console.Println("${r.Status} ${r.Body}")

let p: Http.Response = Http.Post("http://localhost:8080/echo", "text body")?
```

```
class Request {
    Method: String
    Url: String
    Body: String
    fn Init(method: String, url: String)
    mut fn SetHeader(name: String, value: String)
    mut fn SetBody(body: String)
}

class Response {
    Status: I64
    Body: String
    fn Header(name: String) -> Option<String>     // 名前の大文字小文字は区別しない
    fn IsOk() -> Bool                             // 200〜299
}

fn Get(url: String) -> Result<Response, Error>
fn Post(url: String, body: String) -> Result<Response, Error>
fn Send(req: Request) -> Result<Response, Error>
```

- 接続は1回ごとに閉じる(`Connection: close`)。リダイレクトは追わない。本文は `Content-Length`、`Transfer-Encoding: chunked`、接続が閉じるまで、のどれにも対応する
- 送れなかった・読めなかった・形が壊れている、は `Err`(`ErrorKind.Io`)。404や500は `Err` ではなく、`Status` で見る
- 上限: 本文は16MiBまで(超えたら `Err`)
- 既定のタイムアウトは30秒

### サーバー

```
let server: Http.Server = Http.Listen("127.0.0.1", 0)?     // 0: 空いているポートを選ぶ
Console.Println("port ${server.Port()}")
server.Serve((req: Http.Request) => {
    Http.Response.Text(200, "hello ${req.Path()}")
})?                                                         // Close されるまで戻らない
```

```
fn Listen(host: String, port: I64) -> Result<Server, Error>
class Server {
    fn Port() -> I64
    fn Serve(handler: fn(Request) -> Response) -> Result<Unit, Error>   // 接続ごとに async のタスクを1つ作る
    fn Close()                                                           // Serve を終わらせる(別のタスクから呼ぶ)
}
// サーバー側で受け取る Request には、Path() と Query() と Header(name) と Body がある
// Response.Text(status, body) と、SetHeader で作る
```

- `Serve` の中でハンドラが`Panic`したら、`Task`の規則どおり、プログラム全体が止まる

### 入れないもの(この提案では)

- **HTTPS(TLS)**: 暗号の実装は、依存を入れずに安全に書けない。`https://` の URL は `Err`("https is not supported yet")にする。将来、OSの機能(OpenSSL、Windows の SChannel、macOS の Network.framework)を使う別の提案で足す
- HTTP/2、キープアライブ、リダイレクト、Cookie、マルチパート、WebSocket、プロキシ

## 他の案

- `libcurl` に依存する: HTTPS が使えるが、全OSで入っているとは限らず、ビルドが複雑になる。標準ライブラリは外部に依存しない、という方針に反する
- `Process` で `curl` を呼ぶ: 入っているかどうかに左右される
- サーバーを`Async`なしのループ1本にする: 遅いハンドラ1つで全体が止まる

## 影響

- ランタイム: `zevic_net_listen` `zevic_net_accept` `zevic_net_connect` `zevic_net_read` `zevic_net_write` `zevic_net_close` `zevic_net_shutdown`、POSIX と Winsock。Windows では `ws2_32` をリンクする(未検証)
- 標準ライブラリ: `Zevic.Http`(`Zevic.Async` に依存)
- 言語・`zevfmt` への影響なし

## テスト

- 同じプログラムの中で、サーバーを `async` で立て、ループバック(`127.0.0.1`)に対してクライアントで GET・POST・404・chunked・大きな本文・ヘッダーを試す
- 壊れた応答、閉じた接続、`https://` は `Err`
- インターネットには出ない(CI でも動くように)
