# Proposal 0006: JSON (`Zevic.Json`)

- Status: accepted (2026-11-03, implemented the same day)
- Date: 2026-11-03

## Motivation

Configuration files and web APIs (`Zevic.Http`) read and write JSON. The standard library has nothing for it, so you have to cut strings apart by hand.

## Proposal

A new standard library module, `Zevic.Json`. Nothing is added to the runtime; it is written in Zevic alone (RFC 8259).

```
import Zevic.Json

let v: Json.Value = Json.Parse("{\"name\": \"zevic\", \"tags\": [1, 2]}")?
let name: String = v.Get("name").UnwrapOr(Json.Value.Null).AsString().UnwrapOr("?")
Console.Println(Json.Stringify(v))      // {"name":"zevic","tags":[1,2]}
Console.Println(Json.Pretty(v))         // indented by two characters, one element per line
```

```
enum Value {
    Null,
    Bool(Bool),
    Number(F64),
    Str(String),
    List(Array<Value>),
    Object(Map<String, Value>),
}
```

- Accessors: `IsNull()`, `AsBool()`, `AsF64()`, `AsI64()` (only for numbers without a fractional part), `AsString()`, `AsArray()` and `AsObject()` give `None` when the kind is different. `Get(key)` and `At(i)` give `None` when missing.
- `Parse` returns a `Result<Value, Error>`. The error is `ErrorKind.Parse` and includes the line and column ("JSON: unexpected `]`, expected a value at line 1, column 7").
- `Stringify` has no whitespace, `Pretty` indents. Objects keep the order of their keys. If a key appears twice, the later value stays (in the position of the first).
- Strings are written as UTF-8. Only `"`, `\` and control characters are escaped. `\uXXXX` (including surrogate pairs) can be read. A lone surrogate is an error.
- Numbers are `F64`. Integers up to 2^53 are exact. An integer is written as `1` (not `1.0`), and `NaN` and infinity cannot be written, so they become `null`. A number that is too large, such as `1e999`, is an error when read.
- Nesting is limited to 512 levels (more is an error; the stack is never used up).
- Strictly RFC 8259: a trailing comma, comments, `'` strings, a number with a leading `0` (`01`), and a string that contains a raw control character are errors.

## Not included

- Automatic conversion between `Value` and `struct` / `class` (there is no reflection). Write the `Get` calls by hand if needed.
- Streaming (processing while reading), and big integers that do not go through `F64`.
- JSON Pointer, JSON Schema and JSON with comments (JSON5).

## Alternatives

- Splitting `Number` into `I64` and `F64`: large integers such as `9007199254740993` would be exact, but the users would have to handle both. Start with `F64` only and add it if it causes trouble.
- Making an object an `Array<Member>`: the order is kept naturally, but `Get` takes linear time. A `Map` keeps the insertion order, so a `Map` is used.

## Impact

- The standard library only. No impact on the language, the runtime or `zevfmt`.

## Tests

- Reading and the accessors, writing (`Stringify` and `Pretty`), round trips, building values, escapes and numbers, 19 kinds of errors (with positions), and the depth limit.
