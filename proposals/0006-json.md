# 提案 0006: JSON(`Zevic.Json`)

- 状態: 採用(2026-11-03、実装は同日)
- 日付: 2026-11-03

## 動機

設定ファイルやWebのAPI(`Zevic.Http`)では、JSONを読み書きする。標準ライブラリになく、文字列を手で切り出すしかない。

## 提案

新しい標準ライブラリ `Zevic.Json`。ランタイムには何も足さず、Zevic だけで書く(RFC 8259)。

```
import Zevic.Json

let v: Json.Value = Json.Parse("{\"name\": \"zevic\", \"tags\": [1, 2]}")?
let name: String = v.Get("name").UnwrapOr(Json.Value.Null).AsString().UnwrapOr("?")
Console.Println(Json.Stringify(v))      // {"name":"zevic","tags":[1,2]}
Console.Println(Json.Pretty(v))         // 2文字ずつ字下げして、1要素1行
```

```
enum Value {
    Null,
    Bool(Bool),
    Number(F64),
    Str(String),
    List(Array<Value>),
    Object(Map<String, Value>),
}
```

- 取り出し: `IsNull()` `AsBool()` `AsF64()` `AsI64()`(小数部のない数だけ) `AsString()` `AsArray()` `AsObject()` は、種類が違えば `None`。`Get(key)` と `At(i)` は、なければ `None`
- `Parse` は `Result<Value, Error>`。エラーは `ErrorKind.Parse` で、行と桁を含む("JSON: unexpected `]`, expected a value at line 1, column 7")
- `Stringify` は空白なし、`Pretty` は字下げあり。オブジェクトはキーの順番を保つ。同じキーが2回出たら、後の値が残る(順番は最初の位置)
- 文字列は UTF-8 のまま書く。`"` `\` と制御文字だけエスケープする。`\uXXXX`(サロゲートペアを含む)は読める。対にならないサロゲートはエラー
- 数は `F64`。2^53 までの整数は正確。整数は `1` と書き(`1.0` にしない)、`NaN` と無限大は書けないので `null` にする。`1e999` のように大きすぎる数は、読むときにエラー
- 入れ子は 512 段まで(超えるとエラー。スタックを使い切って止まることはない)
- 厳密に RFC 8259: 末尾のカンマ、コメント、`'` の文字列、先頭が `0` の数(`01`)、制御文字をそのまま含む文字列は、エラー

## 入れないもの

- `Value` と `struct` / `class` の自動変換(リフレクションがないため)。必要なら、手で `Get` を並べる
- ストリーミング(読みながら処理する)、`I64` を `F64` に通さない大きな整数
- JSON Pointer、JSON Schema、コメント付き JSON(JSON5)

## 他の案

- `Number` を `I64` と `F64` の2つに分ける: `9007199254740993` のような大きな整数が正確になるが、利用側が両方を扱うことになる。まず `F64` だけにして、困ったら足す
- オブジェクトを `Array<Member>` にする: 順番は自然に保てるが、`Get` が線形時間になる。`Map` は挿入の順番を保つので、`Map` を使う

## 影響

- 標準ライブラリだけ。言語・ランタイム・`zevfmt`への影響なし

## テスト

- 読み取りと取り出し、書き出し(`Stringify` と `Pretty`)、往復、値の組み立て、エスケープと数、エラー19種(場所つき)、深さの上限
